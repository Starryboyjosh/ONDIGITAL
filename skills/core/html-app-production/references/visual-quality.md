# Visual Quality Reference

Use this reference for visual-first HTML, landing pages, rich prototypes, and redesigns.

## Direction Before Code

- Define one visual thesis: mood, material, density, and motion.
- Define one information thesis: what the user must understand or do first.
- Pick a compositional model before picking components: full-bleed media, work surface, editorial grid, canvas/tool, comparison view, or operational shell.

## Quality Rules

- Make the primary object obvious in the first viewport: product, place, workflow, tool surface, dashboard, or playable area.
- Use assets that carry meaning. For real products, venues, portfolios, and brands, prefer real or generated bitmap imagery over abstract gradients.
- Avoid generic SaaS card mosaics unless repeated cards are the actual data model.
- Use cards only for repeated items, modals, framed tools, or content that needs a boundary.
- Keep app UIs quiet and scannable: small headings, clear labels, restrained color, dense but readable spacing.
- Avoid one-note palettes. Use neutral structure plus purposeful accent and state colors.
- Keep typography proportional to context: hero-scale type only for true heroes, compact type in dashboards and panels.
- Do not put explanatory design text in the UI.

## Motion

- Use motion for orientation and feedback: entrance, state change, hover/press, drawer/modal, scroll reveal, or chart update.
- Keep transitions fast and consistent. Respect `prefers-reduced-motion`.
- Remove animations that make repeated workflows slower.

## Failure Checks

- Text overlaps or clips at mobile widths.
- The first viewport is decorative but not useful.
- Headings sound like marketing on an operational tool.
- Buttons are text-heavy where an icon, menu, toggle, slider, or segmented control is the familiar pattern.
- The UI would lose meaning if decorative shadows, glows, or gradients were removed.
